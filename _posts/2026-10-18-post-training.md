# 如何入門大型語言模型 Post-training：從監督式微調到強化學習的技術實踐

## 一、前言：為什麼 Post-training 成為大型語言模型發展的重要技術？

隨著大型語言模型（Large Language Models, LLMs）的快速發展，人工智慧模型的技術競爭，已不再完全取決於預訓練階段所使用的參數規模、資料數量與運算資源。如何在既有基礎模型之上，進一步改善指令遵循、推理能力、專業任務表現及人類偏好對齊，已成為模型開發的重要課題。

這類技術通常統稱為 **Post-training（後訓練）**。

與需要大量資料及高效能運算叢集的預訓練（Pre-training）相比，Post-training 可以利用既有的開放權重模型，透過較具針對性的資料集、訓練方法及評估機制，改善模型在特定任務中的表現。

對於研究人員、軟體工程師及企業 AI 開發團隊而言，Post-training 提供了一條相對容易進入模型研發領域的技術路徑。開發者不必從零建構基礎模型，而是可以從小型開源模型開始，逐步掌握資料處理、模型微調、偏好最佳化及強化學習等技術。

## 二、理解 Post-training 的技術定位

大型語言模型的開發流程，可以概略區分為 Pre-training 與 Post-training 兩個階段。

**Pre-training 的目標，是建立模型廣泛的語言理解、知識表徵及文字生成能力。** 模型透過大量文字、程式碼及其他形式的資料進行學習，掌握語言結構、知識關聯與統計規律。這個階段通常需要大量運算資源，也是基礎模型開發成本最高的環節之一。

相較之下，**Post-training 的目標，是讓已經具備基礎能力的模型，更符合特定任務、使用者需求或預期行為。**

例如，一個經過預訓練的模型，可能已經理解 Python 程式語言，但不一定能夠穩定遵循使用者的程式設計要求；也可能具備醫學相關知識，卻無法按照特定格式產出醫療文件。

透過後訓練，可以進一步改善模型的指令遵循能力、輸出格式一致性、任務處理流程，以及對不同回答品質的判斷。

需要注意的是，Post-training 並不等同於單純的 Fine-tuning。Fine-tuning 是模型參數調整的概念，而 Post-training 涵蓋的範圍更廣，包括監督式微調、偏好對齊、獎勵模型及強化學習等方法。

此外，領域持續預訓練（Continued Pre-training, CPT）也經常出現在完整的模型客製化流程中，但在技術分類上，通常需要與指令對齊及偏好最佳化區分。

## 三、Post-training 的主要技術方法

### 3.1 Supervised Fine-Tuning（SFT）：建立模型的指令遵循能力

監督式微調（Supervised Fine-Tuning, SFT）是最適合初學者入門的後訓練技術之一。

SFT 的核心方法，是準備一組包含使用者指令與預期回答的訓練資料，讓模型透過監督式學習，調整其輸出行為。

例如，企業可以蒐集高品質的客服問答、技術操作說明或特定格式的文件範例，將其轉換為指令與回答的配對資料，再利用 SFT 使模型更熟悉預期的回覆方式。

SFT 通常採用 Token 層級的交叉熵損失（Cross-Entropy Loss），使模型提高產生正確目標序列的機率。

這種方法實作相對成熟，並具有良好的開源工具支援。然而，模型能否透過 SFT 獲得實質改善，仍高度依賴資料品質、模型原有能力及訓練配置。

SFT 特別適合改善回答格式、任務流程及特定指令模式，但不應將其視為解決所有知識缺口或推理問題的通用方法。

### 3.2 Direct Preference Optimization（DPO）：讓模型學習回答品質的差異

當模型已具備基本的指令遵循能力後，下一個重要方向是偏好對齊（Preference Alignment）。

Direct Preference Optimization（DPO）是其中具有代表性的方法。

與 SFT 直接提供標準回答不同，DPO 使用偏好資料，讓模型學習在同一個問題下，哪些回答較符合預期品質。

例如，針對同一個技術問題，資料集可能包含兩種回答：其中一個完整、正確且具有明確步驟；另一個則存在錯誤或不必要的內容。

DPO 會利用這類偏好配對，調整模型對兩種回答的相對機率，使其更傾向產生被偏好的回答。

DPO 的重要特色，是不必先另外訓練明確的獎勵模型，即可直接利用偏好資料執行最佳化。

對於希望改善模型回答品質、專業性及一致性的開發團隊而言，DPO 是從 SFT 進一步理解模型對齊技術的合適起點。

### 3.3 Reinforcement Learning（RL）：透過回饋持續改善模型行為

強化學習（Reinforcement Learning, RL）是後訓練中較進階的技術方向。

傳統的 Reinforcement Learning from Human Feedback（RLHF），通常會利用人類偏好資料建立獎勵模型，再透過強化學習調整語言模型的輸出策略。

近年來，針對數學、程式設計及可自動驗證的推理任務，也發展出利用可驗證獎勵（Verifiable Rewards）的強化學習方法。

其中，Group Relative Policy Optimization（GRPO）是受到關注的代表性方法之一。

GRPO 可以針對同一個問題產生多組候選回答，利用獎勵函數評估各回答的表現，再透過群組中的相對獎勵訊號更新模型。

例如，在數學問題中，可以根據答案是否正確建立獎勵；在程式設計任務中，可以利用單元測試結果，判斷模型產生的程式碼是否符合要求。

這類方法的重要價值，在於讓模型不再只是模仿既有的標準答案，而是透過可衡量的結果回饋，逐步改善解題策略。

不過，強化學習涉及獎勵設計、訓練穩定性、樣本生成與較高的運算成本，因此較適合在掌握 SFT 與偏好最佳化後進一步學習。

## 四、降低訓練門檻：LoRA 與 QLoRA

對於希望使用個人電腦或單張 GPU 進行後訓練的開發者而言，參數高效率微調（Parameter-Efficient Fine-Tuning, PEFT）是必須掌握的技術。

其中最常使用的兩種方法為 LoRA 與 QLoRA。

LoRA（Low-Rank Adaptation）透過在模型的特定權重矩陣中加入低秩適配參數，減少需要更新的參數數量。訓練過程中，原始模型的大部分權重保持凍結，只需更新少量新增參數，即可改變模型行為。

QLoRA 則進一步結合量化技術，通常以 4-bit 形式保存基礎模型權重，並透過 LoRA 訓練額外的適配參數，以降低 GPU 記憶體需求。

必須強調，LoRA 與 QLoRA 並不是 SFT 或 DPO 的替代品，而是降低模型訓練資源需求的方法。開發者可以使用 LoRA 執行 SFT，也可以在合適的訓練框架下使用參數高效率方法進行 DPO。

因此，初學者不必立即租用昂貴的 GPU 伺服器。從參數量較小的開源模型開始，搭配 LoRA 或 QLoRA，即可建立第一個後訓練實驗。

## 五、建立第一個 Post-training 實驗

入門 Post-training，應從明確且可以衡量的任務出發，而不是一開始就嘗試訓練大型通用模型。

例如，可以選擇「讓模型按照固定格式產生中文技術說明」作為第一個實驗主題。

首先，選定合適的基礎模型。對於 GPU 記憶體有限的開發環境，可以使用 Qwen3-0.6B 等小型開放權重模型，先驗證完整的訓練流程。

其次，準備具有一致品質的訓練資料。初期可建立數十筆資料測試流程是否正確，再逐步擴充為數百筆經過人工檢查的範例。資料數量並不存在適用於所有任務的固定門檻，應以模型改善幅度及驗證結果決定是否繼續擴充。

接著，使用 Hugging Face Transformers、TRL 與 PEFT 建立訓練環境，透過 SFTTrainer 搭配 LoRA 執行訓練。

在開始訓練之前，應先以相同的測試問題評估原始模型，作為後續比較的基準。

訓練完成後，應再次執行相同的評估流程，觀察模型在任務正確率、格式一致性及回答品質上的變化。

如果模型已能產生符合基本需求的回答，就可以進一步建立偏好資料，利用 DPO 改善回答品質。

至於 GRPO 等強化學習方法，建議在已建立可靠的模型評估機制，以及可自動驗證的獎勵函數之後，再進行研究與實作。

## 六、資料品質與模型評估比訓練規模更重要

Post-training 的成功與否，不應只以訓練損失是否下降，或模型是否完成訓練來判定。

模型可能在訓練資料上的表現持續改善，卻沒有提升實際應用的品質，甚至因為過度擬合而降低對未知問題的處理能力。

因此，在準備資料時，應建立明確的品質檢查程序，包括確認回答正確性、移除重複資料、檢查標註一致性，以及避免將敏感或未經授權的資訊納入訓練資料。

資料集也應區分為訓練、驗證與測試用途，並確保測試資料不會在訓練階段被使用。

在模型評估方面，除了傳統的 Loss 與 Accuracy，也應依任務特性設計適當的指標。

例如，文件產生任務可以評估格式符合率；程式生成任務可以利用測試案例通過率；專業問答則可以結合人工審查、事實正確性及回答完整性進行評估。

進階開發者也可以使用 EleutherAI 的 LM Evaluation Harness，建立可重複執行的模型基準測試。

對於強化學習而言，獎勵函數的設計尤其重要。若獎勵條件不完整，模型可能學會迎合評分機制，而非真正改善任務能力，形成所謂的 Reward Hacking 問題。

因此，完整的後訓練流程，不只是調整模型權重，而是建立資料、訓練、評估及回饋持續改善的工程能力。

## 七、如何選擇 Post-training、RAG 與其他模型客製化方法？

企業在導入生成式 AI 時，並非所有需求都必須透過 Post-training 解決。

如果主要需求是讓模型查詢最新的產品資訊、企業內部文件或持續更新的專業知識，通常應優先評估 Retrieval-Augmented Generation（RAG）。

RAG 透過檢索外部知識，在模型產生回答時提供相關內容，而不需要每次資料更新都重新訓練模型。

相較之下，如果需求是改善模型的固定輸出格式、指令遵循模式、專業任務行為或特定判斷偏好，Post-training 可能具有較高的應用價值。

兩者並非互斥。企業可以透過 Post-training 改善模型的任務處理能力，再結合 RAG 提供即時且可追溯的知識內容。

在資源有限的情況下，應先建立 Prompt Engineering 與 RAG 的基本應用，再透過實際評估判斷是否有必要投入模型後訓練。

## 八、Post-training 的技術學習路線

對於具備 Python 與基本機器學習經驗的開發者，建議將學習過程分為三個階段。

**第一階段是建立 SFT 的基本能力。**

學習者應理解 Transformer、Tokenizer、Embedding、Loss Function 與反向傳播等基本概念，並使用 Hugging Face Transformers、Datasets、TRL 及 PEFT 完成小型模型的 LoRA 微調。

這個階段最重要的成果，是能夠獨立準備資料集、執行訓練、儲存模型適配器，以及比較訓練前後的模型表現。

**第二階段是理解模型偏好與對齊。**

在掌握 SFT 後，可以開始建立包含 Chosen 與 Rejected 回答的偏好資料集，實際執行 DPO 訓練，並觀察不同偏好資料及訓練設定對模型行為的影響。

這個階段的學習重點，是理解模型為何偏好某些回答，以及如何評估對齊效果。

**第三階段是研究強化學習與推理能力提升。**

進一步學習 Reward Modeling、GRPO、可驗證獎勵、模型採樣策略與強化學習的穩定性問題。

可以從簡單的數學題、格式驗證或程式單元測試開始，建立能夠自動評估生成結果的訓練環境，再逐步研究複雜推理及 AI Agent 任務。

完成這三個階段後，開發者便能從單純使用模型，進一步參與模型能力改善及開源後訓練框架的研發。

## 九、結論：從使用 AI 模型走向改善 AI 模型

Post-training 已成為大型語言模型技術發展的重要組成部分，也讓更多開發者有機會參與模型能力的研究與改善。

與訓練大型基礎模型相比，Post-training 具有相對較低的入門門檻，並能夠利用成熟的開源工具，快速驗證不同訓練方法對模型行為的影響。

對於初學者而言，最重要的並不是一次掌握所有後訓練演算法，而是建立一條循序漸進的學習路徑：**先從 SFT 掌握模型微調的基本流程，再透過 DPO 理解偏好對齊，最後進入 GRPO 與強化學習等進階技術。**

同時，應將資料品質、模型評估與實驗可重現性視為後訓練工程的核心能力，而非只追求更大的模型參數或更高的運算規模。

隨著開放權重模型與後訓練工具鏈持續成熟，Post-training 將不僅是大型 AI 研究機構的專屬技術，也會成為軟體工程師、開源開發者與企業 AI 團隊進入模型研發的重要途徑。
